## 9. Tehnologie & cum construim (arhitectură)

**Stack oficial (decis):**
> **Next.js (App Router) + Payload 3 + PostgreSQL**, deploy pe **Railway**.
> Un singur repo, un singur deploy. Self-hosted, open-source, fără abonamente SaaS.

**De ce:** Payload 3 rulează *în interiorul* aplicației Next.js → frontend + CMS + admin într-un singur app. Frontend 100% custom (orice cod, orice animație), admin inclus pentru Servicii/Proiecte cu relații. Design nelimitat, spre deosebire de temele WordPress.

**Roluri:**
- **Next.js** — frontend-ul public (design, SEO, viteză). Aici bagi animațiile.
- **Payload 3** — admin + API pentru conținut (Servicii, Proiecte, Blog).
- **PostgreSQL** — baza de date (addon pe Railway).

**Colecții în Payload** (se adaugă din admin, fără cod la fiecare):
- **Servicii** — câmpuri: titlu, slug, descriere, preț, imagine.
- **Proiecte** (portofoliu) — câmpuri: titlu, imagine (verticală SAU orizontală — orientarea vine din poză), link live (opțional), **studiu de caz** (rich text, opțional), **relație → Servicii folosite** (multi).
  - Studiu de caz completat → pagină internă de proiect. Necompletat → cardul duce direct la link-ul live. (ca la piersolenski.com/work)
- **Articole** (blog) — motorul SEO din §6.

**Legătura serviciu ↔ proiect (automată):**
Câmpul de relație din Proiecte. Adaugi un proiect, bifezi „Magazin online + Plăți online”, și el apare singur pe paginile acelor servicii. **Zero cod la fiecare adăugare.**

**Fluxul de adăugare (de zi cu zi):**
- Serviciu nou → Admin Payload → *Servicii* → Adaugă → completezi + preț → Publică.
- Proiect nou → Admin Payload → *Proiecte* → Adaugă → screenshot, link, bifezi serviciile → Publică. Apare automat în portofoliu ȘI pe paginile de serviciu.

**SEO (fără plugin):** direct în Next.js — Metadata API (title/meta per pagină), `sitemap.ts`, `robots.ts`, JSON-LD schema, `hreflang` pe .ro/.md/.fr. Vezi §6.

**Ce facem o singură dată (setup):**
1. `create-payload-app` cu template Next.js + adapter Postgres.
2. Definit colecțiile: Servicii, Proiecte (cu relația), Articole.
3. Deploy pe Railway: serviciu Node + addon Postgres, variabile `DATABASE_URI` + `PAYLOAD_SECRET`.
4. Template-uri Next: listă + pagină pentru Serviciu și Proiect, blog.
5. SEO: Metadata API + sitemap + schema.
6. După asta, tot conținutul se adaugă din admin.

**Animații — CORE pentru pagina de acasă** (stil k72.ca), frontend Next, nu afectează CMS:
Lenis (smooth scroll), GSAP (reveal / mask / pin), cursor custom, react-three-fiber (Three.js, la nevoie). Detaliate pe secțiuni în §11.

**Repo & deploy (CI/CD):**
- GitHub: **github.com/alexlescinschi/lescinschiro** — tot codul aici.
- Railway conectat la repo → **push pe `main` = deploy automat**. Zero deploy manual.
- Postgres = addon Railway. Variabile în Railway: `DATABASE_URI`, `PAYLOAD_SECRET`.
- **Media (poze urcate din admin):** discul Railway e efemer → **Railway Volume** sau **Cloudflare R2 (S3)** ca pozele să nu dispară la redeploy.
- VPS-ul propriu rămâne rezervă (Docker: Node + Postgres) dacă mutați mai târziu.

**Cod ≠ conținut (cum stă treaba cu CMS-ul la deploy):**
- Payload rulează ÎN Next → un singur repo, un singur deploy. Push = pagină + CMS împreună.
- **Codul** (pagini, animații, schema colecțiilor) vine din Git → Railway.
- **Conținutul** (texte, proiecte, poze) stă în Postgres, se adaugă din `/admin`, NU prin Git → **nu se pierde la redeploy**.
